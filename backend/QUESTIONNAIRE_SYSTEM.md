## 问卷系统功能

### 1. 问卷管理
- **问卷创建**：支持创建包含多个选项的问卷，可设置标题、描述和是否允许多选
- **问卷查询**：提供问卷列表、详细信息及状态查询接口
- **状态管理**：支持问卷的启用/禁用状态控制

### 2. 问卷提交
- **高并发处理**：问卷提交请求通过Redis快速计数，提高响应速度
- **重复提交防护**：基于用户ID和问卷ID实现提交去重
- **选项验证**：验证用户选择的选项数量是否符合问卷设置

### 3. 实时统计
- **实时数据展示**：提供问卷的实时统计信息，包括各选项的投票数和占比
- **排行榜功能**：根据投票数量对选项进行排序
- **历史快照**：定期生成统计数据快照，便于数据分析

## 分布式设计

### 1. 缓存优先架构
- **Redis计数**：问卷提交首先更新Redis中的计数器，确保快速响应
- **原子操作**：使用Redis Lua脚本保证计数操作的原子性
- **数据验证**：利用Redis Set数据结构验证选项的有效性

### 2. 分布式锁机制
- **Redlock实现**：使用Redis分布式锁保护关键资源的并发访问
- **自动释放**：设置锁超时时间，防止死锁情况
- **安全释放**：使用Lua脚本确保只有加锁的客户端可以释放锁

### 3. 异步消息处理
- **Outbox模式**：使用Outbox表记录待处理的消息，确保数据一致性
- **Redis Streams**：通过Redis Streams实现可靠的消息队列
- **幂等消费**：基于事件ID实现消息的幂等处理，防止重复消费
- **错误重试**：对失败的消息实现指数退避重试机制

### 4. 数据一致性保障
- **事务处理**：在数据库操作中使用Spring事务管理
- **回滚机制**：当消息发送失败时，自动回滚Redis中的计数变更
- **快照备份**：定期生成统计快照，支持数据恢复

### 5. 高可用设计
- **故障恢复**：支持从快照和事件流重建Redis统计数据
- **监控告警**：提供系统运行状态监控接口
- **限流防护**：实现滑动窗口限流，防止系统过载

## API接口

### 1. 创建问卷
- **路径**: `POST /api/v1/question`
- **请求体**: 
  ```json
  {
    "title": "问卷标题",
    "description": "问卷描述",
    "allowMultiple": false,
    "options": ["选项1", "选项2", "选项3"]
  }
  ```
- **返回**: 新建问卷的基本信息

### 2. 获取问卷列表
- **路径**: `GET /api/v1/question`
- **返回**: 问卷摘要信息列表

### 3. 获取问卷详情
- **路径**: `GET /api/v1/question/{id}`
- **返回**: 问卷详细信息，包括所有选项

### 4. 提交问卷
- **路径**: `POST /api/v1/question/submit`
- **请求体**:
  ```json
  {
    "questionId": 1,
    "userId": "user123",
    "optionIds": [1, 2]
  }
  ```
- **返回**: 提交结果确认信息

### 5. 检查提交状态
- **路径**: `GET /api/v1/question/submitted`
- **参数**: `userId`, `questionId`
- **返回**: 用户是否已提交该问卷的状态

### 6. 获取实时统计
- **路径**: `GET /api/v1/question/stats/{id}`
- **返回**: 问卷的实时统计数据，包括各选项票数和百分比

### 数据流向
1. 客户端发起问卷提交请求
2. 服务端校验问卷状态和选项合法性
3. 获取分布式锁保护并发访问
4. 在Redis中执行计数操作
5. 保存提交记录到MySQL
6. 创建Outbox消息并发送到Redis Streams
7. 异步消费者批量处理消息并持久化到数据库
